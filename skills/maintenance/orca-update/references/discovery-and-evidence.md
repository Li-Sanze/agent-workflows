# 发现、证据与恢复边界

按需阅读，不把本页当作固定工具名单、机器配置或通用安装脚本。

## Skill 安装与维护对象是两件事

共享源目录及宿主引用只决定本 Skill 在哪里被发现，不构成本轮软件更新名单。安装记录应在便携 Skill 内容之外标明共享源、引用位置、版本与验证等级，并区分「路径已配置」「宿主原生目录已检测」「实际维护已执行」。已有会话是否需要重载或新开，按宿主当前能力处理；本机安装不代表远程或云端也已安装。

Skill 内容版本以 `SKILL.md` 的 `metadata.version` 为准；安装收据须与该版本及实际源文件一致，发布标签应指向对应内容的提交。修改后同步核对这些记录，不把某次安装记录当作独立的版本权威。

## 从实际入口确定范围

| 当前材料 | 可以确定 | 还不能确定 |
| --- | --- | --- |
| 用户点名的工具与限制 | 本轮明确范围和特别保护项 | 未点名的所有安装都获准更新 |
| 宿主当前启用项与命令覆盖 | 预期启动入口与相关候选 | 工具一定已装，或包装器后的载荷版本 |
| 可执行文件、符号链接与官方安装记录 | 实际载荷和安装渠道 | 宿主一定使用 PATH 中同名入口 |
| 活动进程、近期使用或用户实践记录 | 使用线索与需要保护的会话 | 历史记录仍是当前状态，或停用工具应该补装 |

通常先找当前宿主配置，再解析入口与载荷，必要时交叉查安装记录。用户要求全量已安装工具时按该范围盘点；只要求一个目标时不要顺便升级其他工具。使用信号不足且取舍影响范围时才澄清，不索取能从本机查明的名单。

入口可启动但宿主未检测到时，分别核对当前版本的检测命令、启动覆盖和 PATH；宿主可能只检测默认命令，未采用启动覆盖。启用状态须读取活动 profile 的当前权威存储，旧 JSON 导出或备份不能代替现状。先定位漏检，不仅凭菜单缺项就重装、重新登录或切账号。

检测结果已含目标但菜单仍缺项时，用宿主提供的界面刷新前端检测并重开菜单；后台接口返回成功不证明前端缓存已更新。

确需修复已有工具的发现入口时，修复应在本轮授权内。兼容命令别名只是可选方式：确认无同名冲突并保留恢复方式，继续指向原包装入口，不绕过其代理、直连、参数或账号语义；不把某次命令名、目录或内部刷新接口固化为通用默认值。

## 网络基线记录什么

记录策略和来源：代理或显式直连、地址／端口／协议、自动代理与绕过规则、实际启动参数和环境注入、用户包装器、宿主命令覆盖与账号选择。只记录受影响项，报告中脱敏。不同工具、主机和用户可有完全不同的值；不得从历史案例生成新默认值。

应用、系统、自动代理与环境可能叠加生效；环境为空或监听存在都不是请求路径证明。包装器文件可保持字节一致，而它背后的版本链接正常改变；令牌、运行缓存和版本元数据也可能正常更新。比较前先区分用户策略、预期安装变化和运行态数据，不能要求全部配置文件机械地零漂移。

## 证据按层交付

| 证据 | 支持的结论 | 不要扩大的结论 |
| --- | --- | --- |
| 版本命令、原参数被接受 | 该入口可启动、版本与参数兼容 | 登录、网络或模型调用一定成功 |
| 宿主重新检测结果包含目标 CLI | 本次宿主能发现该工具 | 新建菜单可见、会话启动或账号功能已通过 |
| 目标菜单现场可见 | 该菜单在本次检查中显示目标工具 | 启动、额度或真实模型调用一定成功 |
| 官方发布摘要比对／适用的平台签名检查 | 相应来源和完整性检查通过 | 所有发行渠道都提供同等级证据 |
| 官方 TLS 下载、解包与启动检查，无独立发布摘要 | 已走官方渠道并通过这些检查 | 自算哈希等同官方独立摘要 |
| 所选字段或适当文件前后相同 | 已比较的保护项保留 | 请求已经按预期路由 |
| 目标进程与源端口关联到代理／路由观测 | 这次被观测的连接采用相应路径 | 全部 HTTP 路径、返回码、未来请求或计费均已测 |
| 额度只读响应／当前界面读数 | 对应来源在该时刻的额度可读取 | 截图里的读数永远实时，或明细弹窗操作也已成功 |
| 原会话身份与连接保留 | 对应会话连接恢复 | 所有旧任务无中断、全部新版本已进入旧进程或整机重启已测 |
| 自定义入口与配置保留，离线样例及已有会话的显示、原生采集分别验证 | 所列集成在本次版本与场景下仍工作 | 未来版本、未测路径或绕过本流程的更新也兼容 |

只读分析期间，不为补齐证据而执行用户禁止的探针或写入。记录「本轮读取的历史证据」与「本轮重新验证」的区别。文件存在、模型声称用过 Skill 和结构校验通过，也不能代替真实宿主执行证据。

## 版本差异与交付粒度

比较起点采用更新前实际运行版本；安装前评估以拟更新版本为暂定终点，安装后用实际安装与运行版本复核，安装／运行不一致时并列说明。区间内重复出现的修复合并；不能确认是否已在起点存在时标为「官方本版说明」，不要断言为新增。安装目标若变化，先复核授权与渠道，再重算区间。

| 材料 | 可用于 | 边界 |
| --- | --- | --- |
| 用户截图、更新通知 | 识别候选版本与界面声明 | 不能证明当前下载、安装或运行状态 |
| 官方对应版本发行说明 | 提炼该区间的能力、修正与兼容性声明 | 不证明本机已经验证这些功能 |
| 更新器阶段回执、安装元数据、运行状态 | 分别确认下载、落盘和新进程版本 | 单个阶段不能替代后续阶段验收 |
| 本机安装前后对照 | 证明所选配置、入口与会话的保留情况 | 不把未执行的新功能或全量业务列为通过 |

简报可用「变化｜对本机影响」两列表格，优先列用户相关项。例如官方声明旧终端留在旧宿主时，写清「已有终端继续运行；新宿主修复对新终端生效」，并另列本次实际比较了哪些会话身份。发行说明若提示降级会丢失设置，在切换前保存对应旧字段；旧载荷存在与迁移配置可恢复分别确认。

## 失败位置决定动作

| 位置 | 下一步 |
| --- | --- |
| 来源、完整性或目标入口尚未确认，仍未修改 | 保留旧安装，停止相关切换；调查缺口或向用户说明 |
| 应用未能正常退出，且要求退出后才能替换 | 保持原应用，不热替换或强杀；说明活动任务与所需决定 |
| 当前会话依赖待更新宿主，接续能力尚不明确 | 退出前准备材料并说明，暂停依赖退出的切换；不把宿主内更新一概禁止，也不假定退出后还能询问 |
| 暂存验证完成，尚未切换 | 先复查保护项和用户并行变化，再决定是否切换 |
| 已替换一部分对象，后续失败 | 按本轮变更清单恢复对应对象，逐项核实；不整体覆盖用户现状 |
| 回退条件不足或用户已修改同一对象 | 保留可恢复现场，暂停冲突部分并说明缺口；不冒称已回滚 |
| 程序可启动但额度或界面失败 | 分别定位安装检测、账号与请求来源；不自动改代理或切账号来凑通过 |
| 基线检查仅因宿主版本或托管 helper 哈希变化而提示 REVIEW 或非零退出 | 审查新版启停、调用与协议，结合离线或被动证据判断；不自动改写清单，实际入口、采集或禁网失败仍按失败处理 |

备份包含恢复映射不等于已实测回滚。下载器内部偏移、包布局、进程编号、终端句柄和版本字节数都是现场数据；不作为下轮固定指令。成功和失败分支都须交代暂存对象的去向；仅清理能确认属于本轮且不再需要的对象，不删除必要诊断现场、恢复材料、用户原有会话或仍可能被运行进程使用的旧载荷。
