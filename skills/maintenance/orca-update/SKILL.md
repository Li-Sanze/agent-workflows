# Orca 与 AI 工具受控更新

目标是完成本轮授权的更新，并证明更新前需要保留的行为仍成立。工具名单、安装渠道、版本、路径、代理地址与端口均来自当前环境，不使用历史快照作为固定默认值。

## 先确定本轮授权

- 用户只问版本、影响，或明确「先看／不改」：只读查询并在对话中给结论，不创建备份、脚本或报告，不执行更新。
- 查询命令若可能触发自动更新，改用官方不更新的查询方式或现有安装元数据；不为只读检查永久改动用户的自动更新策略。
- 用户已明确要求更新：可继续必要的盘点、备份、下载、受控安装与验收，不逐步重复请求确认。
- 创建或审计本 Skill 不授权执行真实维护。不得为了验证 Skill 而升级本机程序。
- 更新不隐含安装新产品、切换账号、修改权限策略、改代理／路由／系统网络、迁移安装渠道或强制关闭用户会话的授权。

本 Skill 被调用时才执行相应保护与验收；绕过本流程发起的自动或界面更新，不会自动触发这些检查。对已发生的更新可按当前证据补做复核，不追溯声称更新全程受控，也不承诺未知版本兼容。

## 动态发现目标与基线

优先采用用户点名的范围。用户要求更新相关 CLI 却未列名称时，从宿主当前登记和启用的入口、实际可执行文件、安装记录及使用信号中发现候选；区分「已装且在用」「已装但停用／用途不明」「仅配置未安装」。据请求决定范围，不把发现的所有程序自动纳入更新，也不漏掉用户明确要求的已安装工具。

软件安装记录须核对其来源与时效；Skill 自身的安装收据只描述宿主引用，不能当作待更新软件名单。范围或入口难以判断时，按需读取 [发现、证据与恢复边界](references/discovery-and-evidence.md)。

用户只要求「正在用」的工具时，明确停用且无相反使用证据者跳过并在交付中说明，无须逐项询问；没有活动进程本身不能判定工具停用。只有用途不明且取舍会明显改变范围时才澄清。

分别解析显示名称、启动命令、包装入口、真实载荷与安装渠道。裸命令与宿主配置可能指向不同安装；优先核对本轮实际使用的入口，不能靠 PATH 中的第一个同名命令直接决定。配置了但未安装的工具只报告，不擅自补装。也不扩展为全盘软件扫描。

截图、更新通知与下载缓存只提供目标线索。分别核对更新前的安装版本、运行版本和待安装版本；「可用」「下载完成」「安装完成」「新进程已生效」分开记录。目标以本轮授权和原发行渠道为准，不因检查时出现更高版本而自行扩大范围。

读取用户提供或当前可发现的实践文档，以其了解约定；版本、活动 profile 和实际网络仍须现场核对。只读接口优先；涉及宿主运行状态时使用它当前提供的能力和版本指南，不假定跨版本命令、配置表或存储路径永久有效。

更新前记录受影响范围的：

- 当前版本、安装来源、真实入口、启动参数及包装入口与载荷的关系。
- 实际生效的网络策略及注入位置，包括应用／系统代理、自动代理、环境与绕过规则、包装脚本和显式直连。未见进程代理变量不能直接判为直连。
- 账号选择、认证方式、权限语义和用户特别要求保留的配置；不要把正常令牌续期或运行缓存当作需要字节不变的保护项。
- 已存在且受更新影响的 statusline／HUD／hook 集成：分开记录用户入口与配置、宿主托管 helper 的所有权和调用关系，以及启停、输入协议、降级隔离和请求限制；具体路径、版本与哈希留在本机基线。
- 受影响的活动会话，以及可恢复的旧载荷、配置或状态快照。运行中的数据库用受支持的一致性备份，不直接复制活动主库文件，也不直接编辑它。

基线与备份限于实际需要并妥善保存在本机；输出不包含凭据、完整环境或无关私人配置。切换前复查用户是否已修改相关保护项，不能拿旧快照覆盖并行发生的新变化。

## 版本差异与兼容性

以更新前实际运行版本为比较起点；安装版本与运行版本不一致时并列记录。安装前或只读影响查询以拟更新版本为暂定终点，安装后按实际安装与运行版本复核。读取该区间的官方发行说明，覆盖跨版本的相关增量，并排除起点已有能力。官方材料不可得或区间不完整时，说明来源与缺口，不凭版本号补写功能。

提炼与本轮环境相关的新增能力、行为修正及兼容性影响；优先说明默认值变化、配置迁移、权限变化、旧／新会话何时生效和降级限制。会改变恢复安全的迁移项在安装前纳入备份与恢复映射。Windows、WSL、远端等未涉及的平台只在影响本轮时展开。

发行说明证明官方声明；本机验收证明此次观察到的行为。交付中分别表述，摘要使用短语和具体对象，避免宣传措辞。需要比较示例或证据分级时读取 [发现、证据与恢复边界](references/discovery-and-evidence.md#版本差异与交付粒度)。

## 保留原策略执行更新

**保留更新前的策略，不把所有工具改成统一代理。** 已有代理保留其地址、端口、协议、绕过规则及注入位置；原来显式直连的仍保留直连。不创建或重写包装器来强行符合某台机器的旧示例。外层用户入口与内层版本载荷分开：可以按更新需要切换载荷或版本链接，但入口仍须指向同一产品并保留原有网络、参数和账号语义。

按各目标实际采用的渠道与平台检查版本；不为追求「最新」自行切换发行通道或安装方式。优先走官方更新器和受支持的安装路径。更新器若会覆盖用户包装入口，先核对保留该入口的受支持方式，不能先运行再期待配置自行保留。

下载、更新请求沿用各自原有网络策略，不把协调者环境统一注入所有工具，也不修改全局包源或关闭证书校验来绕过失败。按官方可获得的证据核验来源与完整性；官方没有独立摘要时如实说明证据等级，不能把自行计算的哈希称为官方摘要核验。平台签名／公证等检查按当前平台和发行方式适用，不强套到所有产品。

安装前暂存并验证新载荷，准备本次替换对象的恢复映射，再进行受控切换。应用需要退出时正常退出；存在活动任务且不能确认会话保留方式时，先暂停受影响的重启并向用户说明。不要强制关闭已有任务来完成升级，也不删除仍可能被旧进程使用的载荷。

更新当前承载本会话的宿主前，先核对执行器、控制通道和重连／接续能力，在退出前完成暂存与必要说明。有受支持且已确认的持续执行或接续路径时，可按既有授权继续；否则先准备好可审阅的安装结果与恢复材料，再让用户接手最终切换或选择可持续的执行路径，不能先退出再尝试询问。

没有更新 CLI 子命令时，可使用已核对当前契约、状态和前置条件的应用内置更新接口；仍由官方更新器处理下载、校验和切换。状态回执只证明对应阶段，安装后须重新连接并核对运行版本。不要为自动化而绕过接口的会话保留、签名校验或安装阻塞条件。

下载失败先用受支持的重试或续传能力，设置与任务相称的时间、次数或无进展终点。同一失败没有新信息时不无限重试。手工搬包、解压内部载荷或自制差分下载仅是有当前格式证据、完整性校验和恢复路径时的条件恢复手段；不得照搬旧维护脚本或自行扩展成长期下载工程。

## 分层验收与失败处理

需要判断证据能证明什么，或遇到恢复分支时，读取 [发现、证据与恢复边界](references/discovery-and-evidence.md)。

按受影响目标验证：实际入口的版本和原启动参数、宿主运行状态、重新检测结果与相关菜单可见性、保护配置的语义或适当字段的哈希、账号状态，以及额度等相关功能。入口能启动不等于宿主能发现或菜单可见；额度与实际模型调用也须分别说明证据范围。入口与检测不一致时按参考页排查。

已纳入基线的自定义集成是本轮必需验收项：分别复核用户入口和显示配置、托管 helper 调用与采集启停、输入协议和降级隔离，显示正常不能代替采集链路证据。保留既有禁网等限制；对约定只读现有数据的显示集成，使用离线样例和已有会话的被动读数，缺失时保留缺省或未验证状态，不补发额度请求、新增轮询或向真实采集端注入测试数据。

涉及已安装的 HUD／statusline 适配器时，按需读取 [既有显示集成的维护](references/hud-statusline-maintenance.md)，复核源码与本机清单、原生字段语义、样式保护项和离线自检结果。

网络配置一致只能证明配置保留；需要证明请求路径时，关联目标进程、本地连接与代理／路由观测。正常直连也要按自己的基线验收。默认先用版本、诊断、模型目录或额度等低副作用查询；生成式验证是否执行取决于本轮授权、必要性与成本，不能因加载 Skill 自动增加模型调用。

优先 CLI 或只读 API；确需可视窗口或缺少接口时可用 GUI。输入接收、点击回执、截图读数和功能完成不是同一证据；GUI 失败应标明未验证项目及替代证据，不能假报成功，也不把单次失败变成永久禁用 GUI 的规则。

若涉及会话恢复，比较更新前后的实际身份与连接，说明用户主动关闭或新开的会话。连接保留不能扩大成所有后台任务持续执行、全部模型请求或整机重启已测试。说明新版何时对现有／新启动会话生效。

- **变更前失败**：保留原状并停止受影响分支，不做多余回滚。
- **部分变更后失败**：核对当前状态，只恢复本轮替换对象，保留用户的新变化。不能整库覆盖或声称一个跨多个对象的操作天然原子；无法安全回退时保留现场、说明未完成项。
- **既有集成验收异常**：仅由宿主版本或托管 helper 更新引起的基线差异先复核，不直接判定损坏，也不自动改写清单凑通过。实际失效按本轮变更清单恢复相关用户字段，不整份还原设置或把旧 helper 回灌新版宿主；保留并行变化。
- 完成、暂停、失败或回退时，都明确本轮临时资源的清理或保留责任；在保留必要诊断现场、恢复材料及仍被使用的载荷后，清理已不需要的暂存和下载残片。保留用户原有会话，记录各目标的完成、跳过、失败或未验证状态。

按用户本轮的必需验收项判断完成度：必需项失败或未验证，不能把整体说成成功。可选补充项的证据降级不必否定已证实的主目标，但必须单列限制；用户点名要求的项目不能被擅自降为可选项。

## 何时澄清

先调查能自行查明的事实。仅在缺口会影响目标选择、网络保留、恢复安全或授权范围时，集中说明「已知事实、缺口／冲突、选项及影响」并询问。例如多个实际入口无法判定、使用范围不明且会明显扩大更新、更新器必须改用户配置、重新登录或会话中断不可避免。

只暂停依赖该答案的操作；已经授权且独立的工作可以继续。必要信息或授权仍未到达时，不把等待超时当成回答。已得到的授权不重复索取；也不为文档排版、等价命令或普通可恢复的实现选择频繁打断用户。

## 交付

交付采用紧凑结构，先结果，再版本增量与验收：

- **结果**：目标、前后版本、完成／跳过／失败状态；有跳过项时附理由。
- **版本增量**：用短列表或表格列主要变化与本机影响，附官方来源；不要混入起点已有功能。
- **验收**：入口／运行版本、原网络和账号语义、会话保留；单列必需项缺口及未测边界。
- **恢复与改动**：恢复位置、临时资源去向、是否改动业务项目；只有确需用户处理时列后续动作。

按请求裁剪，不输出盘点流水账。若本轮也修改 Skill，将 Skill 改动与软件发行变化分开说明；结构校验、独立审计和真实维护分别标注验证范围。本 Skill 不自动改用户实践文档、创建项目方案状态或转为代理修复。
